Fe now has mutable value semantics. References are no longer values: `ref` and `mut` are not types, so a struct cannot hold a borrow. Instead they describe how a function or binding accesses a place. A parameter is a read-only view (`x: T`), a mutable borrow (`x: mut T`) or owned (`x: own T`), and `let h = mut p.x` gives mutable access to `p.x` until the last use of `h`. A function that returns `ref T` or `mut T`, or a shape such as `Option<mut T>`, gives its caller access to a place rather than a value, and may `yield` that access and run code after the caller's last use of it, for example to write a value back. A new access checker replaces the borrow checker: an access lasts until its last use, and two accesses to overlapping places conflict unless both only read, so a function can hold mutable access to two fields of one struct at once. Mutable variables are declared with `var x = e`, which replaces `let mut x = e`, and `mut`, `ref` and `var` mark the names a pattern binds, as in `Some(mut v)` and `for mut x in xs`.
