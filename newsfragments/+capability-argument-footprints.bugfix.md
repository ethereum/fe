A capability passed as a data argument to a closure call reaches state as it does for a function call, so a closure that calls out or reads storage through an `Evm` it is passed conflicts with an open storage access instead of losing a write or reading stale state. A parameter bounded only by sealed std capability traits reaches only what they give, so `who<C: Ctx>(ctx)`, a generic effect `uses (c: C)` and a derived event's `emit(mut log)` no longer conflict with an open storage access.
