Added named trait implementations and compile-time trait choices. `impl Price for Item as Wholesale` declares a second implementation of `Price` for `Item` beside the ordinary `impl Price for Item`, and `with (Wholesale) { ... }` makes it the answer for `Price<Item>` in the block: trait and method calls, trait constants, constant patterns, operators, indexing and `for` loops there use it, and generic functions called there receive it through their bounds, supertraits and trait-keyed effect providers included. `core::obligations::prove<G>()` returns an `Evidence<G>`, a compile-time value that records which implementation answers `G`; a generic function can take it as a parameter and open it with `with (evidence) { ... }`, so one function computes 100 with the ordinary implementation and 70 with `Wholesale`. Named implementations are items: `with (W)` finds `W` in scope, `with (lib::W)` names it by path, `use lib::W` imports it and `pub impl Price for Item as W` exports it. A program that would read one choice in two ways is refused: a type, array length or constant argument that depends on an opened choice (8-0122), an implementation with conditions reached through ordinary selection inside a `with`, or an item written inside a `with` that reads the choice it makes (8-0098), evidence stored in a field or a mutable place or chosen at run time, and a named implementation whose associated types differ from the other implementations of its trait for the same type, or of a storage-key or encoding trait (5-0005).
