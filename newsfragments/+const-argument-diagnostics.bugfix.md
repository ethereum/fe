Const arguments and bounds that were silently dropped or misreported are now checked where they are written: faulting or non-const const arguments in trait references, including those of a qualified path's trait, associated-type bindings and bounds, and effect-key arguments. An invalid type in a trait reference's arguments, such as `[u8; true]`, is reported at the argument instead of dropping the bound or blaming the trait. A fault that only an applied default or an evaluated `const fn` reveals is reported at that use, pointing to the faulting computation. The arguments of an effect key or an associated-type bound must now satisfy their bounds (`uses (p: Guarded<bool>)` with `T: Gate` on `Guarded`), and so must a type written as an argument its type alias drops (`Drop<Guarded<bool>>` with `type Drop<T> = u8`), in every position. A trait whose parameter defaults to `Self` can now be an effect key: its provider is asked for itself, as in `Has<X>` for a provider `X`, instead of the unfulfillable `Has<Self>`. Associated-type bindings in `impl` headers are now rejected.
