Safe memory APIs no longer let a size or a count corrupt other allocations. Every allocation goes through `core::ptr::alloc_bytes`, which reverts with `Panic(0x41)` above `2**64 - 1` bytes, as Solidity's allocations do, instead of wrapping the free memory pointer onto live allocations; the unbounded `core::ptr::alloc_raw` is private. This covers `MemBuffer::with_capacity` and `reserve` (and so `Packed::with_capacity` and `TextBuilder::with_capacity`), `ptr::alloc_bytes` itself, and a `packed_width()` that over-reports to `keccak_packed`. `keccak_packed` and `encode_packed` revert with `Panic(0x01)` when a value's `pack_into` writes more than its `packed_width()` instead of writing past the buffer.
