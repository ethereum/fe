An import now resolves to what its path names after all imports are resolved, independent of the order in which imports are resolved. A `use` could keep a name that a glob import brought in even when a named import of the same name, resolved later, shadows it, such as `use foo::X` when `foo` has both `pub use bar::*` and `pub use baz::X`. A `use` in a block could likewise bind its first segment to an outer scope's name that the block's own glob import shadows. A glob-imported name used as the first segment of a `use` path is now reliably reported as ambiguous when an ingot or builtin type has the same name, and imports that depend on each other in a cycle that no single resolution settles, such as `use x as y` and `use y as x` in a block whose outer scope has both, are reported as ambiguous instead of resolving arbitrarily.
