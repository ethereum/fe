APIs that access memory or storage through a raw pointer or numeric slot, or build a safe type from raw parts, are now `unsafe fn`. They include `core::ptr::{copy, zero_bytes, alloc_array}`, `MemArray::new_uninit`, `MemSlice::from_raw_parts`, `core::abi::store_word`, the `from_abi_tail` constructors and the `RawStorage` methods. The `RawMem` effect is removed; raw memory access needs only `unsafe`. `Encode::encode` writes into a bounds-checked `core::abi::AbiFrame` instead of through a raw pointer, so encoders contain no `unsafe` code.
