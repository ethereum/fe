Storage collections are owners at their storage places. A `StorageMap`, `StoragePackedArray`, `StorageBytes`, `StorageHeap` or `TSlot` is no longer a `Copy` handle with a `SALT` parameter: the contract layout gives it a slot, and a map's entry for `key` lies at `keccak256(key ++ slot)` onwards, field after field, like a struct in a Solidity `mapping`. `map[key]` names the entry's place without a call (`core::ops::StateIndex`), so `map[key].count += 1` reads and writes one slot, and map values may be structs and other values that span several storage words. Collection methods take `self` or `mut self` and declare no effects. A library type becomes a collection the same way, by implementing `StateIndex`: `locate(root, key)` returns an entry's slot and bit offset, declares no effects, and may read its `Lanes` codec's `BITS` (`core::ops::LaneCodec`) to step between entries. A collection is pinned to storage or transient storage by its `StateIndex` implementation's `SPACE`, a `core::effect_ref::StateSpace` (a memory collection implements `Index` and `IndexMut` instead), and a type that holds a pinned type is state-only: it cannot be constructed, copied, moved out of storage or kept in a memory value. A field takes its slot number only in the spaces its parts lie in, so a `TSlot` field leaves its storage number free. `unsafe fn at(slot)` places a collection at a runtime slot under `RawStorage`. `SolArray<T>` indexes as a place too: `arr[i]` is bounds-checked against the length (`Panic(0x32)`), an element of 16 bytes or fewer with a Solidity encoding (`SolPacked`) is a lane of a shared slot encoded like Solidity (so `uint24[]` and `bytes4[]` stay storage compatible), and wider or struct elements take their own slots, so arrays of structs are supported; `SolArray`, `SolEnumerableSet` and `SolSlot` are owners at their slots like the other collections, whose raw-slot `at` constructors return a `mut` access. A `mut` access to a packed lane, whether a binding, an argument, a provided effect or a projection's grant, works on a memory copy that is masked back into the slot when the access ends. An `unsafe` block whose tail is a tuple of accesses is an unsafe split, one session whose grants the block promises are disjoint, so two raw-slot collections can be held at once (`let (a, b) = unsafe { (SolArray<u256>::at(x), SolArray<u256>::at(y)) }`); a tuple of projection results anywhere else is rejected, since it would hold copies. Storage and transient contract fields now share one slot numbering. `SolArray::element_slot`/`element_offset` are removed. Migration: drop `SALT` arguments and `= _` defaults, replace `map.ptr(key)`/`map.mut_ptr(key)` and `with (ptr)` blocks with `map[key]`, remove `uses (storage: Field(T))` clauses, and take collections as `mut` or view parameters instead of by value.
