Stored elements can be cleared. `core::ops::clear_storage(mut collection, key)` zeroes the element at `key` of a collection whose elements live in storage or transient storage, where a slot no one wrote reads as zero, so zero is a value of every type there; a collection keeping its elements in memory is rejected by its `where C::SPACE.starts_zeroed()` requirement. The element must be `core::marker::Clearable`, which the compiler implements for scalars, raw pointers and aggregates of clearable types and which cannot be implemented by hand: a value holding a storage collection is not clearable, since zeroing its own slots would leave the collection's entries behind. `StorageMap::remove(key)`, `SolArray::pop()`, `SolArray::clear_at(i)`, `SolArray::clear()`, `TSlot::clear()`, `StorageHeap::pop()` and `SolEnumerableSet::clear()` use it, so `SolArray::pop` zeroes every slot of a struct element and no longer needs `T: Default`, and `StorageHeap::pop` zeroes the slot it vacates. `StorageHeap::at(slot)` places a heap at a runtime slot like the other collections. Underneath, `unsafe fn core::intrinsic::clear<T>(_ place: mut T)` zeroes any place's representation: its bytes in memory, its words in storage or transient storage, and only its own bits of a packed slot.
