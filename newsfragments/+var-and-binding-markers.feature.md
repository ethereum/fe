Binding mutability and access mode no longer share a word. `var x = e` binds a mutable value and replaces `let mut x = e`, which is now an error with a fix-it; `var x: own T` makes an owned parameter mutable, replacing `mut x: own T`, and `var own self` (or `var self: own T`) is a mutable owned receiver, replacing `mut own self`. `mut` always denotes a mutable access and `ref` a read access: `let x = mut p` and `let x = ref p` bind accesses, and in a pattern `mut x`, `ref x` and `var x` mark a binding's mode (`Some(ref v)`, `(i, var x)`, `for ref x in xs`). A plain binding takes a value, as `let x = e` does: a projection's `ref` result is copied if it is `Copy`, so `let v = xs[i]` no longer holds `xs`, and any other `ref` result is an error whose fix is `ref`. A `mut` result bound whole by `let` (`let x = xs.at_mut(0)`) stays an access, but its components take values like a place's, so `Some(mut v)` writes through and a plain `Some(v)` is an immutable copy. A type with no value reading binds its read access under a plain name: a `#[view]` type (`let s = buf.span()`) and a state-only one (`let m = store.balances`). A pattern matched against a place opens each marked binding's access on that binding's own part, so `match p { Pair { ref a, mut b, .. } => … }` leaves `p.c` free. Markers sit on the bound names only: `match ref x`, `let (a, b) = mut t` and `for x in mut xs` are errors whose fix-it moves the marker onto every name. A loop's item pattern chooses its traversal, so `for mut x in xs` writes each element and a method chain traverses mutably too (`for (i, mut x) in xs.enumerate()`); a two-base loop binds both items `mut` or neither. A plain name moves out of an owned place, or through a `mut` access as a hole that must be restored before the access closes: `let v = x; x = Option::None; v` takes the value out of `x: mut Option<T>`.
