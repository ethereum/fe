Binding mutability and access mode no longer share a word. `var x = e` binds a mutable value and replaces `let mut x = e`, which is now an error with a fix-it; `var x: own T` makes an owned parameter mutable, replacing `mut x: own T`. `mut` always denotes a mutable access and `ref` a read access: `let x = mut p` and `let x = ref p` bind accesses, and in a pattern `mut x`, `ref x` and `var x` mark a binding's mode (`Some(ref v)`, `(i, var x)`, `for ref x in xs`). A plain binding takes a value, as `let x = e` does: a projection's `ref` result is copied if it is `Copy`, so `let v = xs[i]` no longer holds `xs`, and any other `ref` result is an error whose fix is `ref`. A `mut` result (`let x = xs.at_mut(0)`) and a `#[view]` one (`let s = buf.span()`) bind their access. A pattern matched against a place opens each marked binding's access on that binding's own part, so `match p { Pair { ref a, mut b, .. } => … }` leaves `p.c` free. A plain name moves out of an owned place, or through a `mut` access as a hole that must be restored before the access closes: `let v = x; x = Option::None; v` takes the value out of `x: mut Option<T>`.
