A `recv` arm's variant path is resolved once, as a type written in the arm. In a named `recv M { .. }` block a single segment names one of `M`'s items, as if written `M::V`, so a generic variant can be handled as `G<u8> { .. }`, and a longer path is resolved where the arm is written. Previously `self::V { .. }` passed the block check and then failed with "`V` is not found", and an arm naming no variant also reported its field bindings as undefined variables. A fieldless variant can now be matched by its path, like `M::U -> u256 { .. }`, in either kind of `recv` block. An arm's path and its block's msg path are checked as any other path is where it's written: a segment that isn't visible is reported, including a variant of the msg that isn't visible from the contract, as are a generic variant named without its arguments, like `G { value }` for `G<T>`, an error in a generic argument, an unmet requirement of a type the path names, and, in a bare `recv { .. }` block, a path that names nothing, like `Gone -> u256 { .. }`.
